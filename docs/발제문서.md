## **Intro :  실전! 대기업 개발자 채용 사전과제 연습**



**과제 소개**

> 다수 서버 환경에서도 안정적으로 동작하는 커피숍 주문 시스템을 구현해 봅시다.
>
1. 커피 주문에 필요한 메뉴를 구성하고 조회가 가능해야 합니다.
2. 커피 주문은 포인트로 가능합니다.
3. 커피 주문 내역을 통해 인기 있는 메뉴를 추천합니다.



🚩

**과제 안내사항**

> **기존 과제들과 다르게 요구사항이 명확하게 정의되어 있지 않습니다.**
>

⏩ 채용 과제는 명확한 정답이 있는 과제가 아니라, 왜 이런 구조로 설계했는지에 대한 본인의 논리를 설명하고 설득하는 것이 중요합니다.

⏩ 동시성 · 데이터 일관성 · 확장성 관점에서 어떤 선택을 했는지를 이유와 함께 명확히 드러내주세요.

⏩ 설계 내용을 정리한 뒤 바로 구현하지 말고, 튜터님과 설계 점검을 먼저 진행한 후 구현을 시작하시기를 권장드립니다.



## 2️⃣ 요구사항 가이드

## 필수 요구사항



**아래 API를 구현합니다. 단, 기술 제약사항을 사전에 고려하여 설계해주세요.**

---

1. 커피 메뉴 목록 조회 API
2. 포인트 충전하기 API
3. 커피 주문, 결제하기 API
4. 인기 메뉴 목록 조회 API

### 0. 문제 해결 전략 수립

> 해당 내용은 `README.md`에 필수로 첨부해야 합니다.
>
- [ ]  설계 내용(ERD, API 명세서)
- [ ]  설계의 의도
- [ ]  선택한 문제해결 전략 및 이 선택을 위해 분석한 내용
- [ ]  기술적 선택 이유

### 1. 커피 메뉴 목록 조회 API

- [ ]  커피 정보(메뉴ID, 이름, 가격)을 조회하는 API를 작성합니다.

### 2. 포인트 충전 하기 API

- [ ]  결제는 포인트로만 가능하며, 포인트를 충전하는 API를 작성합니다.
- [ ]  사용자 식별값, 충전금액을 입력 받아 포인트를 충전합니다. (1원=1P)

### 3. 커피 주문/결제 하기 API

- [ ]  사용자 식별값, 메뉴 ID를 입력 받아 주문을 하고 결제를 진행합니다.
- [ ]  결제는 포인트로만 가능하며, 충전한 포인트에서 주문금액을 차감합니다.
- [ ]  주문 내역을 데이터 수집 플랫폼으로 **실시간** 전송하는 로직을 추가합니다.
  (Mock API나 테스트 코드 등을 사용하여 사용자 식별값, 메뉴ID, 결제금액을 전송합니다.)

### 4. 인기 메뉴 목록 조회 API

- [ ]  최근 7일간 인기있는 메뉴 3개를 조회하는 API를 작성합니다.
- [ ]  메뉴별 주문 횟수가 정확해야 합니다.

## 도전 요구사항


> **아래 4가지 사항을 함께 고려하여 설계 및 구현해주세요.**
>
1. 작성하신 어플리케이션이 다수의 서버에 다수의 인스턴스로 동작하더라도 기능에 문제가 없도록 설계합니다.
2. 동시성 이슈를 고려하여 구현합니다.
3. 데이터 일관성을 고려하여 구현합니다.
4. 각 기능 및 제약사항에 대한 테스트를 작성합니다.

## 추가 조건


1. 인프라 사용에는 제약이 없습니다.
2. API의 HTTP Method들 (`GET` | `POST` | `PUT` | `DEL`)은 자유롭게 선택하세요.
3. 에러 응답, 에러 코드는 자유롭게 정의해주세요.
